# 弥生会計 インポートデータ作成ツール

エクセルと通帳PDFから、弥生会計（デスクトップ版）の**仕訳インポート形式CSV**を作ります。
取り込み前に人が確認すべき点を洗い出した**確認リスト**も併せて出力します。

## できること

- 通帳の取引明細から普通預金の仕訳を起こす
- 摘要・振込名義から勘定科目・補助科目・税区分を自動判定する（ルールはYAMLで編集）
- 消費税額を弥生と同じ端数処理で計算する（インボイス経過措置80%にも対応）
- 元本＋利息のような按分、源泉徴収のような複合仕訳（諸口）を組み立てる
- 通帳の印字残高との突合、貸借一致、預金増減の一致を自動で検算する

## 使い方

### 通帳から普通預金の仕訳を作る

```bash
python3 tools/generate_passbook.py \
    clients/<関与先>/passbook.csv \
    clients/<関与先>/rules.yaml \
    --opening 200551 \
    --from 2025-07-01 --to 2026-06-30 \
    --out out/普通預金.csv \
    --review out/確認リスト.md
```

`--opening` には期首（前期末）の預金残高を渡します。これが合っていれば、
通帳に印字された差引残高との突合で転記ミスが必ず検出できます。

### エクセルから売上・経費の仕訳を作る

```bash
python3 tools/generate_excel.py sales    売上入力.xlsx   rules_sales.yaml --from ... --to ... --out ...
python3 tools/generate_excel.py expenses 経費精算書.xlsx rules_keihi.yaml --from ... --to ... --out ...
```

同じ取引が通帳とエクセルの両方に載っていることがあります。二重計上を避けるため、
片方のルールに `exclude: true` を書いておくと、その取引は仕訳になりません。

### OCRした通帳PDFで転記を裏取りする

```bash
python3 tools/verify_ocr.py clients/<関与先>/passbook.csv OCR済み通帳1.pdf OCR済み通帳2.pdf
```

通帳のスキャンにOCRをかけたPDFがあれば、手で起こした金額がOCR側にも現れるかを
確認できます。桁が英字に化けている分（`4a393` → `48,393` など）は読み替えます。

判定は3段階です。

| 判定 | 意味 |
| --- | --- |
| 確認済み | OCRにも同じ金額がある |
| 未確認 | OCRがその行を拾えていない。**転記との矛盾ではありません** |
| 要確認 | 同じページに1桁違いの数字がある。読み違いの可能性 |

OCRは失敗するページがあるので、これは補助的な確認です。転記の裏取りは
差引残高の連鎖が主で、こちらはその上に重ねる二重チェックとして使ってください。

### 取り込む前に全体を確かめる

```bash
python3 tools/summarize.py out/*.csv
```

複数のCSVをまたいで科目別に集計します。売掛金の計上と回収、現金の引出と経費が
つながっているか、貸借が一致しているかをここで確認してください。

## 通帳CSVの作り方

スキャンした通帳PDFにはテキスト層がないため、読み取り結果をいったん次の形式のCSVにします。

| 列 | 内容 |
| --- | --- |
| `date` | 取引日（`YYYY-MM-DD`） |
| `kind` | `in`=お預り / `out`=お支払 |
| `summary` | 摘要欄の表示（`カード` `振込1` `為替手数料` など） |
| `counterparty` | 振込依頼人・振込先の名義 |
| `amount` | 金額 |
| `balance` | 差引残高（印字がある行だけ。**検算に使う**ので必ず入れる） |

`balance` を入れた行が検算のチェックポイントになります。1桁でも読み違えると
そこで止まるので、桁の読み間違いがそのまま帳簿に入ることはありません。

## 経費精算書を読むときの注意

関与先が手入力している経費精算書は、右端の「金額」欄が空のまま費目欄にだけ
金額が入っている行があり、合計行のO列も式が崩れていることがあります。
金額の正は費目欄（宿泊費〜その他）のほうなので、そちらから読みます。

読み取ったあと、各月シートの合計行（費目欄の合計）と突き合わせて検算します。
一致しなければ行を取りこぼしているので、生成を止めます。

## 消費税の取扱い

税区分ごとの税額は、内税の切捨てとインボイス経過措置の端数処理を弥生に合わせてあります。

少額特例（税込1万円未満の課税仕入れはインボイスの保存を要さず全額控除できる）を
使う場合は、ルールYAMLに次を書きます。基準期間の課税売上高が1億円以下、または
特定期間が5千万円以下の事業者が、令和5年10月1日から令和11年9月30日までの
課税仕入れについて適用できます。

```yaml
small_amount_special:
  apply: true
  threshold: 10000
```

これを入れると、1万円未満の課税仕入れは `deduction` の指定にかかわらず全額控除で
計算します。適用要件を満たさない関与先では `apply: false` にしてください。

## 出力する弥生インポート形式

25列固定・ヘッダーなし・Shift_JIS・改行CRLF。列の並びは `yayoi_import/journal.py` の
`COLUMNS` を参照してください。

複合仕訳は同一伝票No.の連続行として書き出し、片側を諸口にしています。
**最初の取り込みだけは少数行で試して、弥生側の取り込み結果を確認してください。**
列の並びや税区分の表記は弥生のバージョンで差があり得ます。

## 関与先データの取り扱い

このリポジトリは公開されています。関与先の実データ（通帳CSV・エクセル・出力CSV）は
`.gitignore` で除外してあり、コミットされません。`clients/` 配下に置いてください。
`clients/_example/` だけが匿名のひな形として追跡対象です。
